Findings from the first next-steps review of the site (2026-08-25). Re-check each item's current state before re-surfacing — this is a snapshot, not a live status.

**Broken / should fix first:**
1. `lib/about-content.ts` — nearly every social/portfolio link on the About page is a dead `href: '#'` (instagram, twitter, youtube, deviantart, artfight, toyhouse, github, codepen, "the blog"). Only behance/dribbble are correctly marked `soon: true` (which renders disabled via `components/about-tabs.tsx`). The rest look live but go nowhere.
2. `lib/about-content.ts` line ~47 (art tab intro) — copy reads "Soon I will be publishing my portfolio on this site," but `/work` already exists and is fully built. Stale copy contradicting shipped functionality.
3. `components/site-footer.tsx` — Instagram link is a bare `https://instagram.com`, not an actual profile handle.
4. `next.config.mjs` — `typescript.ignoreBuildErrors: true` is set (leftover v0.app scaffold default). This silently hides type errors at build time; worth turning off once the codebase is stable, so TS actually catches regressions.

**Half-done / close to finished:**
5. `lib/work.ts` `WorkPiece` type has no `image` field, so every /work item (including collections) renders `WorkPlaceholder`'s tinted color swatch — this is a documented deliberate design choice (see project_shape.md), not an oversight. BUT real art assets already exist in `public/art/*.png` for at least 3 slugs that also appear in `WORK` (moon-hare, lamplight, the-weight-we-carry via `lib/content.ts` ARTWORKS). Wiring those specific existing images into the matching WorkPiece entries would be low-risk, high-payoff finishing work — flag as a strong "next" candidate, but confirm the placeholder look isn't intentional/permanent before treating it as unfinished.
6. `app/about/page.tsx` has no portrait/photo despite `public/about/portrait.png` sitting unused on disk.
7. `public/science/hero.png` is also unused anywhere in the codebase — check whether it belongs somewhere (e.g. a science section) or should be removed.

**Polish / nice-to-have:**
8. `components/doodle-field.tsx` (`DoodleField`) appears to be orphaned dead code — not imported anywhere, fully superseded by the more sophisticated `IconScatterField` in `components/hero-icon-collage.tsx`. Candidate for deletion.
9. No `app/sitemap.ts`, `app/robots.ts`, or `opengraph-image` — notable gap given the rest of the site has careful per-page `generateMetadata` (see work detail pages).
10. No test runner or eslint config at the project root. `lib/work.ts` has pure, easily-unit-testable functions (`filterWork`, `getCollectionPiece`) if the user ever wants a safety net around the gallery filter logic. Low priority for a personal site — only raise if the user brings up reliability/regressions.

**Explicitly NOT flagged as problems (verified, working as intended):**
- No raw `<img>` tags anywhere — next/image used consistently.
- No TODO/FIXME/lorem ipsum found in source.
- Responsive (sm:/md:/lg:) Tailwind variants present throughout the reviewed components (site-nav, site-footer, work-gallery, home page panels, hero).
- All 4 route pages have metadata (static `metadata` export or `generateMetadata`).
